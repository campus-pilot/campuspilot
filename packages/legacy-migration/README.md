# CampusPilot legacy migration

This private workspace package migrates only Prem Chandra Public School from a
restored, read-only legacy PostgreSQL snapshot into the empty CampusPilot Plus
database. The executable policy is the typed decision set in `src` plus every
tracked Markdown file in [`../../migration/doc`](../../migration/doc). It never
connects to the live legacy database.

The legacy and target deployments use the same S3 bucket. The importer retains
the exact verified legacy keys for the school logo and active templates. S3 is
read-only throughout this migration: no object is copied, uploaded, overwritten,
re-keyed, or deleted. Admission photos and generated/notice PDFs follow the
tracked omission policy and are reconciled without touching their objects.

## Tracked approval contract

No signing key or detached signature is used. The mapping is generated by the
dry run from the canonical typed decisions; operators cannot substitute a
different policy. `approval.json` is a checksum bundle identifying the reviewed
run. It must bind:

- the Prem Chandra school ID and target environment;
- mapping, dump, object-manifest, source-manifest, snapshot-evidence, and
  exception-report SHA-256 values;
- the canonical decision-set SHA-256 and the SHA-256 of all tracked migration
  documentation;
- exact source/target Drizzle history and source-table digest SHA-256 values;
- source version and credential-free source/target database identities;
- the shared S3 bucket, region, endpoint, path-style mode, and exact retained
  object-key allowlist;
- the target PostgreSQL runtime identity and observed Kubernetes writer fence;
- the clean importer Git commit and importer checksum; and
- a stable run ID plus approver/audit timestamp.

Import recomputes all facts against the read-only restored snapshot. It rejects
any policy, checksum, row, ID, relationship, required-field, finance projection,
exam agreement, catalog, or object-key divergence before target writes.

The only migrated password credential is the approved Prem staff credential.
The user/account IDs and Scrypt hash bytes are preserved exactly; provider
tokens, expiry fields, OAuth accounts, API keys, verifications, and sessions are
omitted. `emailVerified` is preserved and provider image is omitted.

Every exam gets its approved `exam_assessment_settings.totalWorkingDays=81`.
Attendance and co-scholastic values must agree across all populated subject
results; approval booleans must be present and equal for every subject. Finance
projections are rebuilt from events. Number counters start at bill `363`,
receipt `154`, refund `1`, and the standalone manual fallback uses exactly
`Legacy manual charge; source did not record a separate justification.`

## Target safety and durability

The CampusPilot Plus API must remain at zero desired/current/ready/available
replicas through database recreation and import. The legacy API may remain
running because the importer reads only the retained snapshot. Immediately
before writes, the importer rechecks the exact target identity, role, TLS,
writer fence, migration history, and emptiness under an advisory lock and a
serializable transaction.

`legacy_migration_run` records preparing, committed, failed, and finalized
states with immutable provenance. The database commit includes the committed
run record. Six audit artifacts are written and checksum-attested before
verification finalizes the run. A failed pre-commit database transaction is
rolled back; S3 needs no rollback because it is never mutated.

Production uses non-login `campuspilot-plus-owner`, dedicated login
`campuspilot-plus-migration`, and non-owner runtime login `campuspilot-plus`.
The tracked migration entrypoint applies runtime DML/sequence grants and revokes
all runtime access to migration control objects. The runtime role cannot own or
alter schema objects, disable triggers, or use the migration run GUC.

## Release checks

The compatible release must include the legacy `expl_`, `exrs_`, and `ett_` ID
support, Drizzle migrations, runtime-grant entrypoint, and this migration
package. Local type checks, application build, Drizzle frozen-history checks,
and Terraform recreation safety gates are mandatory. The service integration
suite remains visible but is temporarily non-blocking for this rollout; this is
not evidence that service-backed migration testing passed.
